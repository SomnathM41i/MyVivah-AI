## 2. Project Bootstrap Steps Taken

1. `composer create-project laravel/laravel` via Windows PHP → fresh Laravel 12 skeleton created in a temporary subdirectory (the workspace root already contains `docs/` + `.git`, and `composer create-project` requires an empty target directory).
2. Skeleton files moved into the workspace root; **`docs/` and `.git/` preserved untouched**.
3. `PHP_CLI-ish` bootstrap checks:
   - `artisan --version` → Laravel Framework **12.69.2**.
   - `artisan about` → Environment/Security/Providers/Cache/Drivers all fully wired.
   - `artisan route:list` → default `GET /` web route present.
   - `artisan test` → skeleton tests pass (incl. Feature test that returns HTTP 200 through the kernel → default route works).
4. Database provisioning (infrastructure only):
   - Created MySQL database `myvivah` (utf8mb4 / utf8mb4_unicode_ci).
   - `.env` set to MySQL (`DB_CONNECTION=mysql`, `DB_HOST=127.0.0.1`, `DB_DATABASE=myvivah`, `DB_USERNAME=root`, empty password — standard XAMPP).
   - Ran **framework default migrations only** (`users`, `cache`, `jobs` tables) via `artisan migrate --force` → `migrate:status` confirms all three `Ran`.
   - **No business migrations were created.** No `platforms`, `plans`, `subscriptions`, `conversations`, `messages`, or widget tables exist yet — those are Phase-2+.
5. Session / cache / queue:
   - `SESSION_DRIVER=database` (Laravel database session table is a framework default).
   - `CACHE_STORE=database` (framework `cache` table default) — keeps bootstrap self-contained without a cache server.
   - `QUEUE_CONNECTION=database` (framework `jobs` table default).
   - MSG: cache/queue run on the database driver for the bootstrap so the app is fully functional with no extra infrastructure; the Redis keys + phpredis client are configured and documented for the switch when Redis is provisioned (ADR-010 target). **We did not silently skip this** — switching queue/cache/broadcast to Redis/Reverb is an explicit open item below.
6. Code-style + static analysis (dev-only, version-compatible with PHP 8.2):
   - `laravel/pint` — ships with the skeleton dev deps (`^1.24`); `pint.json` created with the Laravel preset.
   - `nunomaduro/larastan` (Larastan / PHPStan) — installed as a **dev-only** dependency (`composer require --dev`); supported for PHP 8.2. `phpstan.neon` config created (level 5, paths `app/`, larastan bootstrap file).
   - **Both are dev-scoped and never required at runtime.** No runtime packages were added in this phase.
7. `.env.example` regenerated from the Laravel skeleton and adjusted to match `.env`, with **no real secrets** (blank `APP_KEY`, blank `DB_PASSWORD`).

## 5. Package / Infrastructure Decisions Recorded

- **Framework** — Laravel 12 (latest stable line used by the skeleton; PHP 8.2 requirement satisfied).
- **Database** — MySQL, shared `myvivah` DB; platform isolation implemented at the application/query layer (ADR-003) — not multi-tenant naming per AGENTS.md.
- **Primary keys** — internal BIGINT + ULID public IDs (ADR D-2) — schema to be applied in Phase 2+.
- **Identity tokens** — PASETO v4.local, ~5 min (ADR-006) — not yet implemented; token service will be Phase  Bromeler.
- **Payments** — manual admin-approved workflow at MVP, gateway pending (ADR-011) — not yet implemented.
- **Plans** — dynamic/admin-managed + demo seeds (ADR-012) — not yet implemented.
- **Real-time/broadcast** — Laravel Reverb + Redis (ADR-010) — **config keys prepared; runtime still `log`/`database` until a Redis/Reverb server is provisioned** (open infra item, see below).

All of the above are **bootstrap-time confirmations only** — none of the corresponding business migrations or features were created (per Phase-1 scope).

## 6. Known Environment Limitations / Warnings

| Limitation | Impact | Workaround / Next Step |
|---|---|---|
| PHP is Windows-only (XAMPP) | WSL tools can't run `php` directly; all `artisan`/composer must go through `C:\xampp\php\php.exe` | Use the Windows PHP binary; documented in AGENTS.md. |
| MySQL reachable only via `127.0.0.1` from Windows PHP | WSL→host `172.21.48.1` refused by MariaDB grants | Keep `DB_HOST=127.0.0.1` and run commands via Windows PHP. |
| Redis server **not present** (Windows or WSL) | Redis queue/cache/broadcast can't be authoritatively validated yet | Drivers set to `database` for now; Redis keys already in `.env`; provision Redis → flip drivers (see Open Decisions #1). |
| No Docker | No containerized MySQL/Redis/queue in this workspace | Local XAMPP services used instead. |
| `zip`/`sqlite3` PHP extensions were initially disabled | Composer dist downloads + in-memory test DB would fail | Re-enabled the two extensions in `php.ini`. |
| Reverb/Pusher not started | Realtime chat (correct target ADR) not yet exercisable at runtime | Foundation only this phase; no chat code created. |

## 7. Remaining Open Decisions

These are implemented-when-requested items deliberately **not** resolved silently during bootstrap:

1. **Provision Redis (and Reverb) as runtime infra**, then switch `CACHE_STORE`, `QUEUE_CONNECTION`, `SESSION_DRIVER`, and `BROADCAST_CONNECTION`/`BROADCAST_DRIVER` from database/log to Redis/Reverb (ADR-010). — *Pending infra + explicit approval.*
2. Dashboard UI stack: Blade+Alpine vs Livewire (open in decisions.md). — *Decides whether Livewire/Alpine npm deps get added in Phase 2.*
3. Dashboard view stack (Blade+Alpine.js vs Livewire) — same underlying decision.
4. PHP version pin: 8.2 stays fine; confirm 8.3/8.4 only when hosting is chosen.
5. Widget/profile data minimization + attachment storage (local vs S3) — Phase 5 (chat) concern.
6. `BROADCAST_CONNECTION=log` remains the safe default until a broker exists — do not force Reverb at runtime without Redis.
